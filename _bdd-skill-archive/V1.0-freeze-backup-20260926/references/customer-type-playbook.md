# 客户类型判定与保留策略

BDD 业务的客户分六类，**判错类型会导致策略全错**：给工程公司报终端价会被嫌贵，给高校报项目方案会被嫌重，给中间商讲技术故事是白费口舌。

> **V1 冻结变化**：本文件已瘦身。移出内容（决策周期 / 报价路径 / 资料开放 / 价格敏感度 / 完整策略矩阵）归档至
> `D:/Case Flow/_bdd-skill-archive/V1.0-freeze/customer-type-playbook.strategy-columns.md`
> 原因：这些属销售打法与执行策略，超出「BDD 客户完整企业背调 + 客户开发判断」范围。
>
> **保留列**：优先级 / 商业风险 / 核心推手 / 首要动作——这四项属开发判断。

## 判定优先级

按顺序判断，命中即停。**判据必须来自 Evidence，不得凭印象。**

```
① 经营范围含"环保工程""环境工程""水处理设备""环保科技"？ → 环保工程公司
② 高校 / 研究院（.edu.cn / .ac.cn 邮箱、学校研究所地址）？ → 科研院所高校
③ 名称含"设计院""规划设计""工程咨询"？                    → 设计院
④ 有实体工厂 + 自身产生废水？                             → 终端业主
⑤ 参保 < 20 人 + 无实体厂 + 问得笼统 + 要低价？            → 贸易商 / 中间商
⑥ 以上均不成立 / 信息不足                                 → Unconfirmed
```

**`Unconfirmed` 不是失败，是正确输出。** 信息不足时不得选择"最像"的一类。

## 一、终端业主（工厂）

| 项目 | 内容 |
|---|---|
| 定义 | 自己产生废水、自己有排放责任的企业 |
| 识别信号 | 有工厂地址、有产线、行业明确、谈的是"我们的废水" |
| 核心诉求 | 稳定达标、通过验收、不停产、售后有保障 |
| 敏感点 | **最怕运行不稳定和售后找不到人** |
| 推荐联系岗位 | 环保负责人 / 技术总工（详见 `contact-role-map.md`） |
| 推进要点 | **环保处罚 / 整改期限是最强推手** |
| 常见误区 | 直接找老板谈技术往往无效，应先取得环保负责人的技术认可 |

**关键动作**：查环保处罚记录，作为 Demand Evidence 的证据来源之一。

---

## 二、环保工程公司（EPC / 集成商）

**定义**：承接废水处理工程总包或分包，采购电极 / 设备集成的公司。**走量主渠道。**

| 项目 | 内容 |
|---|---|
| 识别信号 | 经营范围含"环保工程"；不产生废水；谈的是"某个项目"；要技术参数 |
| 核心诉求 | 方案能通过、成本可控、有厂家背书、能配合投标 |
| 敏感点 | 重视技术参数和响应速度 |
| 推荐联系岗位 | 工艺 / 技术工程师（详见 `contact-role-map.md`） |
| 推进要点 | **配合投标**的能力；提供选型支持与小试数据支撑 |
| 常见误区 | 把工程公司当业主讲应用故事 |

**⚠️ 最高商业风险类型**：往往是同时在谈 3~5 家供应商比价的来源。
**策略**：先确认项目真实性（有无中标、有无业主授权），再释放技术资料。**Commercial Risk 通常为 High 或 Medium。**

**反向机会**：查到某项目中标方是工程公司 → **开发中标方比开发业主更快**。

## 三、设计院

| 项目 | 内容 |
|---|---|
| 识别信号 | 名称含"设计院""规划设计""工程咨询"；邮箱多为机构域名 |
| 核心诉求 | 准确的设备参数用于出图、做概算 |
| 敏感点 | 时间紧（按图审节点）、要参数规范、要厂家资质 |
| 推荐联系岗位 | 工艺设计师（水处理专业）（详见 `contact-role-map.md`） |
| 战略定位 | **不直接采购**，是影响力节点。**最高杠杆的客户类型，常被销售忽视** |
| 推进要点 | 帮设计师把方案做进去 = 锁定后续采购 |
| 常见误区 | 认为设计院"不下单"就不重视 |

**商业风险**：Low。

---

## 四、科研院所 / 高校

| 项目 | 内容 |
|---|---|
| 识别信号 | .edu.cn / .ac.cn 邮箱；学校或研究所地址；"课题组""实验室""研究" |
| 核心诉求 | 小批量电极做实验、性能稳定、有检测报告、可写论文 |
| 敏感点 | 单价敏感度**低**；更在意参数稳定性与数据可复现 |
| 推荐联系岗位 | 课题负责人（老师）/ 博士生（详见 `contact-role-map.md`） |
| 推进要点 | 快速响应、完整检测报告；长期价值在**论文引用与口碑** |
| 常见误区 | 用项目销售话术对待，过于啰嗦 |

**商业风险**：Low。
**战略价值**：低成本的技术验证与背书来源。

---

## 五、贸易商 / 中间商

| 项目 | 内容 |
|---|---|
| 识别信号 | 参保人数少、无实体厂、经营范围杂；**一上来就问最低起订量**；不愿透露终端客户 |
| 核心诉求 | 差价；要求独家或区域代理 |
| 敏感点 | 极度价格敏感 |
| 推荐联系岗位 | 负责人 / 老板（详见 `contact-role-map.md`） |
| 推进要点 | **终端信息确认前不投入技术支持资源** |
| 常见误区 | 为拿到"大单"承诺而给出超常条件 |
| **风险** | ① 套取价格信息 ② 以客户名义套技术方案转售 ③ 无法提供售后，损害品牌 |

**商业风险**：High（无终端信息时）。

---

## 六、Unconfirmed（类型未确认）

| 项目 | 内容 |
|---|---|
| 触发 | 判定优先级 ①~⑤ 均不成立，或主体信息不足以判定 |
| 推荐联系岗位 | 保持现有接触点，不主动升级（详见 `contact-role-map.md`） |
| 推进要点 | `Next Action` 应为"通过提问确认客户类型" |
| 常见误区 | 强行归为最接近的一类 |

## 保留策略矩阵速查

| | 终端业主 | 工程公司 | 设计院 | 科研院所 | 贸易商 | Unconfirmed |
|---|---|---|---|---|---|---|
| 优先级 | 高 | **最高（走量）** | 高（杠杆） | 中 | 低 | 待定 |
| 商业风险 | Low | **High/Medium** | Low | Low | High | Unknown |
| 核心推手 | 环保处罚/整改期限 | 项目中标 | 图审节点 | 实验进度 | 差价 | — |
| 首要动作 | 推进寄样 | 确认真实性 | 进入规格 | 快速响应 | 索要终端信息 | 确认类型 |

> 本表**不含**决策周期 / 价格敏感度 / 报价路径 / 技术资料——那四列已归档。

## 组合客户（重要）

| 组合 | 判定 | 处理 |
|---|---|---|
| 工程公司 + 业主一起出现 | 主导方是工程公司 | 按工程公司策略，业主在场时控制参数披露 |
| 设计院推荐 + 业主采购 | 双节点 | 先服务设计院定规格，再跟业主 |
| 工程公司自称"我们有个项目"但无中标信息 | 高风险 | Commercial Risk = High，不释放技术资料 |
