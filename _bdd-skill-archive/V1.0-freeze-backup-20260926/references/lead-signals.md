# Lead Signals · 检索指引

**本文件只负责"去哪里找、找到什么算证据"。判定由 `evidence-policy.md`、`bdd-fit-rules.md`、`bdd-relevance-rules.md` 负责。**

> 本文件不做适配度判断。此前的行业适配度星级表已移交 `bdd-fit-rules.md`（Industry Fit）与 `wastewater-signal-map.md`（特征识别）。

**对应工作流位置**：SKILL.md **第 3 步 Evidence Collection**。检索产物同时服务于第 2 步 Company Verification（第二节）与第 4 步 Company Profile。

---

## 一、BDD 行业三件套（检索优先级最高）

普通背调工具查工商、查规模。**本行业真正精准的信号是这三样**，因为它们直接指向"是否存在强制治理需求"。

### 1. 环保处罚记录 ★★★

| 项 | 内容 |
|---|---|
| **证据价值** | 政府公示的处罚记录 = 独立第三方证据，指向"存在治理需求"。是 Demand Evidence 升到 `Strong Signal` 的主要来源之一 |
| **检索方式** | `"{公司名} 环保处罚"` / `"{公司名} 行政处罚 生态环境"` / `"{公司名} 超标排放"` / 当地生态环境部门行政处罚公示栏目 |
| **取证要求** | FACT，**必须有 Source（公示页 URL 或部门名称 + 公示日期）** |

判断要点：

| 信号 | 说明 |
|---|---|
| 近 12 个月内被处罚 | 时效内，信号有效 |
| 处罚事由涉及 COD / 氨氮 / 特征污染物超标 | 与本行业应用相关 |
| 多次被处罚 | 原有工艺长期不达标 |
| 已公开整改方案 | 项目可能已在推进 |

> **不要把处罚记录直接写成结论。** 它只是证据，最终等级由 `evidence-policy.md` 的 Demand Evidence 映射表确定。

### 2. 环评公示 / 排污许可证 ★★★

| 项 | 内容 |
|---|---|
| **证据价值** | 项目最早的公开信号，**通常比询盘早 3~12 个月**；环评文件往往载明水量、废水种类、执行标准 |
| **检索方式** | `"{公司名} 环境影响评价"` / `"{公司名} 环评公示"` / `"{公司名} 排污许可证"` / 地方生态环境局建设项目环评审批公示 / 全国排污许可证管理信息平台 |
| **取证要求** | FACT，必须附 Source |

判断要点：
- 环评写明"新建废水处理站"或"废水处理设施改造" → 明确设备需求
- 环评载明的废水种类、水量、排放标准 → **可作为客户技术数据（Source：环评公示）**，但仍需确认时效
- 已过审批进入建设期 → 采购窗口

### 3. 招投标信息 ★★☆

| 项 | 内容 |
|---|---|
| **检索方式** | `"{公司名} 招标 废水"` / `"{公司名} 采购 水处理"` / 政府采购网 / 各省公共资源交易中心 |
| **取证要求** | FACT，必须附 Source |

判断要点：
- 已发招标公告 → 有明确预算、决策链已启动
- **中标方是环保工程公司 → 该工程公司可单独作为潜在客户开发**（转身开发中标方可能比开发业主更快）
- 招标技术要求载明水量、水质、标准 → 可作为客户技术数据（Source：招标文件）

### 4. 辅助信号 ★☆☆

| 信号 | 说明 |
|---|---|
| 招聘环保工程师 / 水处理操作工 | 有设施在运行或即将运行 |
| 新增产线 / 扩产公告 | 废水量可能增加 |
| 集团上市 / 融资 | 合规压力上升 |
| 新闻中的技改项目 | 可能配套废水改造 |
| 官网有"环保"栏目并披露指标 | 重视合规 |

辅助信号本身**不足以**把 Demand Evidence 提升到 `Strong Signal`（属间接信号 → `Potential`）。

## 二、主体信息核实

**服务三处**：
1. **Company Verification 公司核实**（SKILL.md 第 2 步）→ 确认主体唯一、名称准确、在营
2. **Company Profile 公司概况**（SKILL.md 第 4 步）→ 填充概况字段
3. **Customer Type 客户类型**（SKILL.md 第 5 步）与 **Commercial Risk**（第 9 步）

| 查什么 | 为什么 | 检索方式 |
|---|---|---|
| 成立时间 | 新公司需谨慎 | 企业信用信息公示系统 / 公开企业信息页 |
| 注册资本 | 参考项 | 同上 |
| 参保人数 | **最接近真实规模的数据** | 企业年报公示 |
| 是否实体工厂 | 有厂址 + 有环保设施 = 真实业主 | 卫星地图、招聘信息中的厂址 |
| 经营范围 | 含"废水处理""环保工程" → 可能是工程公司 | 工商信息 |
| 是否为分公司 / 子公司 | 影响决策链长度与联系角色 | 股权结构 |
| 邮箱域名 | 企业域名 vs 免费邮箱 | 域名反查 |
| 官网是否真实运营 | 空壳站信号 | 访问官网、看更新时间 |

**取证要求**：以上均属 FACT，必须有 Source；无法确认的写 `UNKNOWN`。

### Company Verification 三态判定

| 结果 | 判据 |
|---|---|
| `Verified` | 工商全称查得到 + 存续在营 + 与客户自述名称一致 + 无重名歧义 |
| `Partially Verified` | 主体存在，但名称有出入 / 部分字段缺失 / 与客户自述地址不符 |
| `Unverified` | 查不到主体；或重名无法区分 |

**硬规则**：`Unverified` 时**不得选择最像的一家**，须列入 Missing Critical Data（"需客户提供工商全称"）。主体错 = 全盘错。

**规模参考（需业务方校准）**：
- 参保人数 < 20 人 + 无实体工厂 → 大概率是贸易商或中间商
- 参保人数 > 200 人 + 有工厂 → 终端业主概率高

## 三、检索输出的标准格式

**第 2 步只产出 Evidence，不产出判定。**

```markdown
| # | 类型 | 结论 | Source | Reason | Confidence |
|---|---|---|---|---|---|
| 1 | FACT | 2026-03 因 COD 超标被处罚 | {公示页 URL} | — | High |
| 2 | FACT | 参保 320 人 | 企业年报公示 | — | High |
| 3 | INFERENCE | 废水可能含酚类 | — | 焦化行业工艺描述 | Medium |
| 4 | UNKNOWN | 环评公示 | — | — | — |
```

规则：
- 每条**只写一个结论**，不得合并
- 无 Source 的信息**不得标 FACT**
- 查不到写成 UNKNOWN，**不写"未发现异常"**（未查 ≠ 无）

## 四、常见检索失败的处理

| 情形 | 处理 |
|---|---|
| 中小企业公开信息极稀薄，几乎查不到 | 输出多条 `UNKNOWN`，并在 Missing Critical Data 中列出"建议客户直接提供的材料"。**这是常态，不是检索失败** |
| 名称有歧义 / 重名 | 输出 `UNKNOWN`，标注"主体待确认"，不得选择最像的一家 |
| 只有 B2B 平台信息 | 可标 FACT，但 Confidence = `Low` |
| 信息互相矛盾 | 两条都列出，标注"来源冲突"，不给结论 |
| 客户自述信息与公开信息冲突 | 两条都列出，优先采信公开来源，并标注冲突 |
