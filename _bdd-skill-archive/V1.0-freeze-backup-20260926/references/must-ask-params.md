# 必问参数清单与数据合理性自检

**用途**：生成 `Missing Critical Data`（该向客户要什么），并校验客户已给数据的可靠性。

> **V1 冻结变化**：本文件原含 Quotation Readiness 门槛（四态枚举 / 5 项报价门槛 / Manual Override / 报价流程归属），
> 已移出 Skill → 归档至 `D:/Case Flow/_bdd-skill-archive/V1.0-freeze/must-ask-params.quotation.md`
> 原因：报价条件判断属商务流程，超出「BDD 客户完整企业背调 + 客户开发判断」范围。
>
> **保留的核心**：必问参数清单、参数合理性自检、数据缺失处理原则——这三项服务的是"**该问什么**"，属客户开发判断。

---

## 一、关键参数（Missing Critical Data 的生成依据）

以下 5 项为**能推进决策**的关键参数。缺失时列入 `Missing Critical Data`。

| # | 参数 | 为什么关键 |
|---|---|---|
| ① | 水质类型（行业 / 特征污染物） | 决定工艺路线方向 |
| ② | 进水 COD（或目标污染物浓度） | 决定污染负荷 |
| ③ | 处理水量 m³/d | 决定设备规模量级 |
| ④ | 目标限值或执行标准 | 决定处理深度要求 |
| ⑤ | 盐度 / 氯离子含量 | 影响电极选型与副产物风险 |

> **注意**：本 Skill 只输出"缺哪几项"，**不输出任何报价状态判断**（如"是否具备报价条件"）。报价条件由人工 / 商务系统判断。

## 二、必问参数清单（按客户类型分支）

### A. 通用必问（所有客户，8 问）

可直接复制发给客户：

```
1. 废水所属行业及主要生产工艺？
2. 进水 COD 及 BOD₅ 浓度？（改造项目请提供近 3 个月检测报告）
3. 氨氮 / 总氮 / 总磷浓度？
4. 处理水量（m³/d）及运行方式（连续 / 间歇）？
5. 需要达到的排放标准或目标限值？（请提供标准编号）
6. 氯离子 / 含盐量 / 电导率？
7. pH、悬浮物（SS）、色度？
8. 现有处理工艺及当前出水数据？是否有未处理的高浓度母液？
```

### B. 终端业主加问（4 问）

```
9.  是否需要通过环保验收？有无整改期限要求？
10. 可用场地面积及层高？是否有防爆要求？
11. 现有污水站由谁运维？是否接受外包运维？
12. 项目预算范围及审批时间节点？
```

### C. 环保工程公司加问（4 问）

```
13. 项目是否已中标？业主方是哪家？
14. 需要我方提供电极 / 模组，还是整套集成设备？
15. 项目时间节点与需求量（电极面积或台数）？
16. 是否需要我方配合投标技术文件？
```

### D. 设计院加问（3 问）

```
17. 需要哪些规格参数用于设计？
18. 图审 / 出图时间节点？
19. 是否可将 Boromond 写入设备选型清单？
```

### E. 科研院所加问（3 问）

```
20. 所需的电极形态、尺寸、数量？
21. 实验体系（电解质类型、目标污染物）？
22. 是否需要检测报告 / 第三方性能数据？是否需要发票？
```

### F. 贸易商加问（3 问）

```
23. 终端客户名称及应用行业？
24. 年采购量预估及交付节奏？
25. 是否需要区域保护？具体要求？
```

## 三、参数合理性自检

生成情报卡前做一致性检查，异常项必须回问，**并在附录 A 中标注为 FACT 或 INFERENCE**。

| 检查项 | 异常信号 | 处理 |
|---|---|---|
| COD vs BOD₅ | COD < BOD₅ | 数据错误，回问 |
| 氨氮 vs 总氮 | 氨氮 > 总氮 | 数据错误，回问 |
| 水量 vs 规模 | 与客户描述的产线规模不匹配 | 回问 |
| 检测时效 | 报告超过 6 个月 | 标注"检测时效存疑"，建议重新取样 |
| 检测资质 | 无 CMA 资质报告 | 标注"数据不可直接用于设计" |
| 单位 | 混用 ppm / mg/L / 万 mg/L | 统一为 mg/L 后确认 |

**为什么必须做**：客户提供的参数错误率不低（尤其非专业对口人员转述）。用错误参数推进，到小试阶段才发现，浪费双方 2~4 周。

## 四、客户提供数据的证据标注（遵循 `evidence-policy.md`）

客户提供的数据**必须标注来源类型**，不得直接当成已验证事实：

| 数据来源 | 类型 | 标注写法 |
|---|---|---|
| 客户提供 CMA 检测报告 | **FACT** | `Source: 客户提供检测报告（{日期}）` |
| 客户方口头/文字陈述 | **FACT** | `Source: 客户自述`（Confidence = Low） |
| 客户说"大概""差不多" | **INFERENCE** | 需 `Reason`；或直接标注"客户口径，未经检测确认" |
| 客户未提及 | **UNKNOWN** | 列入 `Missing Critical Data` |

**硬规则**：`客户自述` 是合法 Source，但 Confidence 只能为 `Low`；不得因客户说了就升级为高可信。

## 五、数据缺失的处理原则

| 缺失情况 | 不要做 | 要做 |
|---|---|---|
| 客户不知道水质数据 | 不要用同类行业经验值替代 | 建议送 CMA 检测，或先寄水样做小试 |
| 客户只给一个 COD 值 | 不要据此做任何判断 | 列入 Missing Critical Data |
| 客户说"大概""差不多" | 不要采信具体数值 | 标注"客户口径，未经检测确认" |
| 客户拒绝提供盐度 / 氯离子 | 不要跳过 | 列入 Missing Critical Data |
| 客户要求"先给个大概价" | 不给任何数字 | 输出缺项清单 + 小试建议（**报价判断由人工处理**） |
