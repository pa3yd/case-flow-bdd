# 技术资料开放边界

**这是本 Skill 最重要的风控文件。**

BDD 行业"免费水质检测 + 方案定制"是标配服务，这导致**套取方案与工艺参数是本行业最高频的损失来源**。竞争对手、工程公司、中间商都可能以客户名义索要资料。

原则：**卖产品可以卖参数，卖方案不能卖工艺。**

---

## 一、三档分类

### ✅ 可直接给（无审批，任何人索要均可提供）

| 资料 | 说明 |
|---|---|
| 公司资质证照 | 营业执照、高新技术企业、ISO、专利清单 |
| 电极产品通用规格书 | 外形尺寸、可用面积、基体类型、掺硼浓度等级 |
| 产品目录与宣传册 | 公开版本 |
| 通用技术原理说明 | BDD 电化学氧化的原理性介绍（不涉及工程参数） |
| 公开案例目录 | **仅行业 + 地区 + 规模量级，不含客户名称与具体参数** |
| 出厂检测报告 | 单批产品的常规电化学检测（析氧电位等） |
| 第三方性能检测报告 | 材料级性能，非工程项目数据 |
| 标准品规格与交付条件 | 规格、起订量、交期。**具体价格由商务系统出具，Skill 不承载金额** |

### ⚠️ 需审批（需业务负责人确认，且视客户类型开放）

| 资料 | 开放条件 |
|---|---|
| 脱敏案例详情 | 仅对**终端业主**（已确认项目真实性）开放，隐去客户名 |
| 小试报告（他方项目） | 仅对**已签保密协议**的工程公司开放 |
| 选型计算说明（过程） | 仅对**设计院**开放，用于配合出图 |
| 工艺路线框架 | 仅给**路线层级**（如"预处理+BDD+生化"），不给参数 |
| 非标定制方案 | 需先确认需求真实性 + 商务条件 |

### ❌ 不给（任何情况下均不对外，包括"客户坚持要"）

| 资料 | 原因 |
|---|---|
| **电流密度、停留时间、电流效率、比能耗** | **核心工艺参数 = 全部技术壁垒**。拿到这些，同行可反推全部设计 |
| 具体项目的完整设计参数 | 同上 |
| 客户名单与联系方式 | 公司核心资产 |
| 报价明细与成本构成 | 底价泄露 = 后续所有谈判失守 |
| 供应商与供应链信息 | 可被绕过 |
| 电极制造工艺细节 | 核心技术 |
| 未公开的研发方向与在研产品 | 战略信息 |
| 未脱敏的小试报告 | 含客户信息与全部参数 |

## 二、索要行为识别（危险信号）

本节有两个用途：
1. 触发资料收紧（✅ → ⚠️ → ❌）
2. **作为 Commercial Risk 定级的判据来源**（映射表见 `evidence-policy.md` 第五节）

> **判据只用询盘当时可观察的事实。禁止使用"最终是否成交"作为依据。**

| 危险信号 | 真实含义 | 风险指向 |
|---|---|---|
| 一上来就要"技术方案"和"选型计算" | 目标是方案而非产品 | High |
| 反复追问电流密度、能耗、停留时间 | 目标是工艺参数 | High |
| 拒绝提供水质数据，但要求出方案 | 无法验证需求；或本身就是同行 | High |
| 说"我们有很多项目"但拿不出一个具体项目 | 无明确需求 | High |
| 同时索要多份不同行业的脱敏案例 | 在做案例收集 | High |
| 要求提供客户联系方式做"回访" | 挖客户资源 | High |
| 邮箱域名是同行公司 | 直接识别 | High |
| 拒绝签保密协议但坚持要案例 | 明确套资料意图 | High |
| 要求"先把方案发来看看，合适再谈" | 常见套方案话术 | Medium |
| 对价格不敏感，只对参数敏感 | 本行业价格敏感是常态，异常需警惕 | Medium |
| 只问价格，不问技术 | 纯比价倾向 | Medium |
| 无上述信号 | — | Low |
| 信息不足无法判断 | — | Unknown |

**定级规则**：出现任一 High → `Commercial Risk = High`；无 High 但有 Medium → `Medium`；均无 → `Low`；无法判断 → `Unknown`。

## 三、标准应对话术

### 场景 1：客户索要详细工艺参数

> "具体工艺参数需要结合您的实际水质做小试后才能确定，不同水质的参数差异很大，直接给参数反而可能误导您。**建议您先寄 5~10 L 水样过来，我们做小试后出具完整报告**，包含去除效果和运行数据，这样对我们双方都更可靠。"

**逻辑**：把"不给参数"转化为"需要先做小试"——这是行业标准流程，客户能接受，且直接推进到寄样。

### 场景 2：客户索要完整方案但水质数据不全

> "方案设计需要以您的实际水质为依据。目前我们还需要 **[X]、[Y]、[Z]** 三项数据。您提供后我们 24 小时内出方案。"

### 场景 3：客户要求参考案例

> "我们有多个 **[行业]** 的工程案例。按客户保密约定，我不能提供项目名称和详细参数，但可以提供**行业、处理规模和达到的标准**供您参考。如果您希望了解具体运行情况，我们可以安排您与客户方在双方同意的前提下交流。"

### 场景 4：怀疑对方是同行

> 不要点破，也**不要停止沟通**（对方可能是真客户）。改为：只提供 ✅ 档资料，一切技术细节统一回复"需小试后确认"，不推进寄样以外的任何深度沟通。

### 场景 5：客户催报价（见 must-ask-params.md）

> "为准确核算设备规模与运行成本，需先确认 [X]、[Y]、[Z]。这几个参数直接决定电耗和配置，按估算值报价可能产生较大偏差。"

## 四、可交换原则（不要一味防守）

资料不是只能给或只能不给。**健康的做法是交换：**

| 客户想要 | 你换取 |
|---|---|
| 详细方案 | 完整水质检测报告（CMA） |
| 脱敏案例详情 | 具体项目信息 + 联系人确认 |
| 小试报告 | 签署保密协议 |
| 选型计算 | 承诺将 Boromond 写入设计规格（设计院） |
| 进入正式报价流程 | 明确需求量 + 采购时间表 + 终端信息 |

> **注意**：左列是"客户想要的东西"，右列是交换条件。
> **不要把价格当作可交换的筹码写进本文件**——价格口径由商务系统承载。

**填写话术模板**：
> "这部分资料我们需要您先提供 **[X]**，走完内部流程我这边就能安排。"
