# 必问参数清单与 Quotation Readiness 门槛

---

## 一、Quotation Readiness 门槛（硬性规则）

### 输出只有四个状态，**不输出任何金额**

| 状态 | 触发条件 |
|---|---|
| `Ready for quotation` | 5 项关键参数齐 **且** 资料边界已确认 |
| `Not ready` | 缺商务条件（需求量、交付节奏、采购时间表） |
| `Need technical data` | **Technical Fit = Insufficient Data 且缺关键技术参数（自动串联）** |
| `Engineer review` | 涉及技术判定，需工程师确认 |

### 必须齐备的 5 项

| # | 参数 | 为什么必须有 |
|---|---|---|
| ① | 水质类型（行业 / 特征污染物） | 决定工艺路线方向 |
| ② | 进水 COD（或目标污染物浓度） | 决定污染负荷 |
| ③ | 处理水量 m³/d | 决定设备规模量级 |
| ④ | 目标限值或执行标准 | 决定处理深度要求 |
| ⑤ | 盐度 / 氯离子含量 | 影响电极选型与副产物风险 |

### 串联规则（唯一允许的自动推导）

```
Technical Fit = Insufficient Data
        且
缺少 ①~⑤ 中任一关键技术参数
              ↓
   Quotation Readiness = Need technical data
```

**此规则由 Technical Fit 直接串联，不需要单独推理。** 不要在 Quotation Readiness 环节重新判断技术数据是否充分。

### 人工覆盖（Manual Override）

允许人工规则覆盖，用于「标准产品可直接报价」等特殊场景。

**格式**：
```
Quotation Readiness: Ready for quotation（Manual override：标准品现货，规格已确认）
```

**要求**：
- 必须标注 `Manual override`
- 必须附**覆盖理由**与**依据**
- 未标注的覆盖视为无效

> 金额一律由商务系统 / 报价单承载，**Skill 不承载任何价格数据**。

### 客户催促时的标准回应

> "为准确核算设备规模与运行成本，需要先确认 **[X]、[Y]、[Z]** 三项。这几个参数直接决定电耗和设备配置，若按估算值报价，后续可能出现较大偏差，对双方都不利。您提供后我们给出准确方案。"

**核心逻辑**：不是"我不肯报价"，而是"我要给你准确的价"。

## 二、必问参数清单（按客户类型分支）

### A. 通用必问（所有客户，8 问）

可直接复制发给客户：

```
1. 废水所属行业及主要生产工艺？
2. 进水 COD 及 BOD₅ 浓度？（改造项目请提供近 3 个月检测报告）
3. 氨氮 / 总氮 / 总磷浓度？
4. 处理水量（m³/d）及运行方式（连续 / 间歇）？
5. 需要达到的排放标准或目标限值？（请提供标准编号）
6. 氯离子 / 含盐量 / 电导率？
7. pH、悬浮物（SS）、色度？
8. 现有处理工艺及当前出水数据？是否有未处理的高浓度母液？
```

### B. 终端业主加问（4 问）

```
9.  是否需要通过环保验收？有无整改期限要求？
10. 可用场地面积及层高？是否有防爆要求？
11. 现有污水站由谁运维？是否接受外包运维？
12. 项目预算范围及审批时间节点？
```

### C. 环保工程公司加问（4 问）

```
13. 项目是否已中标？业主方是哪家？
14. 需要我方提供电极 / 模组，还是整套集成设备？
15. 项目时间节点与需求量（电极面积或台数）？
16. 是否需要我方配合投标技术文件？
```

### D. 设计院加问（3 问）

```
17. 需要哪些规格参数用于设计？
18. 图审 / 出图时间节点？
19. 是否可将 Boromond 写入设备选型清单？
```

### E. 科研院所加问（3 问）

```
20. 所需的电极形态、尺寸、数量？
21. 实验体系（电解质类型、目标污染物）？
22. 是否需要检测报告 / 第三方性能数据？是否需要发票？
```

### F. 贸易商加问（3 问，缺则降级处理）

```
23. 终端客户名称及应用行业？（不提供则只报标准价）
24. 年采购量预估及交付节奏？
25. 是否需要区域保护？具体要求？
```

## 三、参数合理性自检

生成判断卡前做一致性检查，异常项必须回问，**并在附录 A 中标注为 FACT 或 INFERENCE**。

| 检查项 | 异常信号 | 处理 |
|---|---|---|
| COD vs BOD₅ | COD < BOD₅ | 数据错误，回问 |
| 氨氮 vs 总氮 | 氨氮 > 总氮 | 数据错误，回问 |
| 水量 vs 规模 | 与客户描述的产线规模不匹配 | 回问 |
| 检测时效 | 报告超过 6 个月 | 标注"检测时效存疑"，建议重新取样 |
| 检测资质 | 无 CMA 资质报告 | 标注"数据不可直接用于设计" |
| 单位 | 混用 ppm / mg/L / 万 mg/L | 统一为 mg/L 后确认 |

**为什么必须做**：客户提供的参数错误率不低（尤其非专业对口人员转述）。用错误参数推进，到小试阶段才发现，浪费双方 2~4 周。

## 四、数据缺失的处理原则

| 缺失情况 | 不要做 | 要做 |
|---|---|---|
| 客户不知道水质数据 | 不要用同类行业经验值替代 | 建议送 CMA 检测，或先寄水样做小试 |
| 客户只给一个 COD 值 | 不要据此判断技术可行性 | 列入 Missing Critical Data |
| 客户说"大概""差不多" | 不要采信具体数值 | 标注"客户口径，未经检测确认" |
| 客户拒绝提供盐度 / 氯离子 | 不要跳过 | 列入 Missing Critical Data，`Technical Fit = Insufficient Data` |
| 客户要求"先给个大概价" | 不给任何数字 | 回复状态 + 缺项清单 + 小试建议 |

## 五、报价流程归属说明

**Skill 只回答"该不该进报价流程"，不回答"报多少"。**

| 事项 | 归属 |
|---|---|
| 判断是否具备报价条件 | ✅ 本 Skill（输出四态之一） |
| 判断缺哪些参数 | ✅ 本 Skill（Missing Critical Data） |
| 具体价格、区间、阶梯价、折扣 | ❌ 商务系统 / 报价单 |
| 成本构成、底价 | ❌ 商务系统 |

**为什么**：价格时效敏感（写死在规则文件里，调价后即失效且无人维护），且属商务决策，不该由检索型工具承担。
