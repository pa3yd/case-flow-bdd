### 变更 8 · `Missing Critical Data` → `Missing Critical Information`（三级优先级）

| | V1.0 | V1.1 |
|---|---|---|
| 字段名 | `Missing Critical Data` | **`Missing Critical Information`** |
| 组织方式 | 平铺清单（按客户类型分支 A~F） | **三级优先级**：`Business` → `Project` → `Technical` |
| 输出格式 | 无强制格式 | `[Business] … [Project] … [Technical] …` |
| 加问清单 | 按六类客户分支 | **按 Path 分支**：通用 / End-user / Partner·EPC / Partner·Distributor / Partner·Technology Partner |

**三级定义**

| 级别 | 回答什么 | 优先级 |
|---|---|---|
| `Business` | 这家公司**值不值得**投入 | 最高 |
| `Project` | 有没有**具体项目**在推进 | 中 |
| `Technical` | 技术参数**够不够**做评估 | 最低 |

**新增硬约束 25**：`What Is Missing` 必须按 Business → Project → Technical 排列。

### 变更 9 · Commercial Risk 修复 + 新增 Financial Warning

| | V1.0 | V1.1 |
|---|---|---|
| 危险信号范围 | 未限定观察时点 | **仅行为型，须在询盘当时可观察** |
| `Unknown` vs `High` | 易混 | **明确 `Unknown` ≠ `High`**；矩阵空格已补齐 |
| 定级规则 | 2 条 | **修正后 3 条**（含 `Unknown` 处理） |
| 新增字段 | — | **`Financial Warning`**：`Yes` / `No` / `Unknown`（仅三值，不是评级） |
| `Financial Warning` 作用 | — | 触发 `Yes` → `Sales Conclusion` **上限降至 `建议先验证`**（**不是一票否决**） |

**背景**：V1.0 中 `Commercial Risk` 在 5 次实跑中**结构性恒为 `Unknown`**，因为判据依赖"是否成交"这类结果论信息。V1.1 改为只采信询盘当时可观察的行为信号。

**`Financial Warning` 硬规则**：不得扩展为财务评级系统；`Unknown` 不得当作负面；`Yes` 需有 FACT 级来源；不得用"公司大不大"推断财务健康度。

### 变更 10 · 新增 `Sales Conclusion`（五值）+ 五色语义 + PDF 双输出

| | V1.0 | V1.1 |
|---|---|---|
| 结论字段 | 只有 `Next Action` | **`Sales Conclusion`**（五值 + 1~2 句原因） |
| 配色 | 无颜色 | **五色语义**（唯一来源，不得扩展） |
| 主卡 | 1 屏 · 10 字段 · 无颜色 | **1 页 · 13 字段 · 大白话 · 五色** |
| 交付 | 仅 Markdown | **Markdown + PDF（三页业务员版）** |

**`Sales Conclusion` 五值**

| 取值 | 含义 | 颜色 |
|---|---|---|
| `建议重点开发` | 证据充分、无重大风险 → 优先配置资源 | 🟢 |
| `建议开发` | 有明确机会，但需求或风险尚有未确认项 | 🟢 |
| `建议先验证` | 机会已识别，但关键信息缺失 → 先补信息再决定投入 | 🟡 |
| `暂不优先` | 机会低，或存在实质风险 / 财务警示 | 🔴 |
| `信息不足，暂缓判断` | 连"值不值得查"都还无法判断 | ⚪ |

**判定顺序**：第 1 步一票否决 → 第 2 步信息不足 → 第 3 步重点开发 → 第 4 步建议开发 → 第 5 步建议先验证。**新增硬约束 22：不得引入数值评分 / 100 分制 / 加权总分。**

**五色语义**：绿 = Confirmed / Positive / High；黄 = Potential；红 = Risk / Conflict；灰 = Unknown；蓝 = Neutral facts。**颜色由字段取值机械映射，不得人工调整，不得表达程度。**

**PDF 三页结构**

| 页 | 标题 | 内容 |
|---|---|---|
| Page 1 | Customer Snapshot | 主卡 + 三个固定小块 |
| Page 2 | Why This Customer | 判读说明 |
| Page 3 | Key Evidence | 附录 A · 按 `Decision Impact` 排序 |

**新增硬约束 24**：PDF 渲染层不得新增、推断、改写任何结论（渲染与判断隔离）。
